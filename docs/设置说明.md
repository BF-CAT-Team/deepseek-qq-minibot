# 设置说明

> 本文档由 `Bot.App.exe --dump-params` 从参数注册表生成，改代码后重新生成即可，不要手改表格。

## 1. 设置放在哪里

三个入口，改的是同一份东西：

| 入口 | 适合谁 | 说明 |
| --- | --- | --- |
| 配置页 `http://127.0.0.1:8765` | 所有人（推荐） | 双击 exe 后自动打开；改完点保存，除少数项外**不用重启** |
| `data\settings.json` | 想批量改 / 备份的人 | 明文 JSON；程序退出时不要手改，改完重启 |
| 数据库 `data\bot.db` | 排查问题 | `chat_state` 表存每群的上轮摘要与冷却时间；不要手改 |

`settings.json` 里同时存着 **AppID / AppSecret / API Key 的明文**。把这个文件夹发给别人之前，先删掉 `data\settings.json`（或整个 `data\`），让对方重新填。

## 2. 参数是怎么合并的

三层，后面的覆盖前面的：

```text
预设（省流 / 平衡 / 体验）
  ↓ 覆盖
全局覆盖（settings.json 的 parameters）
  ↓ 覆盖
单群覆盖（settings.json 的 chats[chatId].parameters）
  ↓ 校验
生效值
```

- **只存覆盖项**：和预设相同的值不会写进配置文件，所以换预设时不会被旧值钉住。
- **越界不拒绝启动**：非法值回退默认并记一条告警（配置页顶部会显示告警数），机器人不会因为一个参数写错就掉线。
- **互相约束**会自动修正：`history_keep_tokens` 必须小于 `session_token_cap`；`adaptive_min_sec` 不能大于 `adaptive_max_sec`。

## 3. settings.json 结构

```jsonc
{
  "preset": "balanced",          // economy | balanced | experience
  "parameters": {                 // 全局覆盖，只写与预设不同的项
    "session_max_turns": 30,
    "trigger_keywords": ["火锅", "烤肉"]
  },
  "llm": {
    "baseUrl": "https://api.deepseek.com",
    "apiKey": "sk-…",              // 明文，注意保管
    "timeoutSeconds": 30,           // 单次请求超时
    "maxOutputTokens": 512          // 输出上限；思考模式会连推理一起算
  },
  "qq": {
    "adapter": "qq",               // qq | mock（mock 不需要凭据，可本地试聊）
    "appId": "…",
    "secret": "…",
    "sandbox": false,               // 沙箱环境
    "receivesAllMessages": false,   // 群主已开「接收所有消息」时的手动兜底
    "extraIntents": 0               // 额外订阅位，一般留 0
  },
  "persona": {
    "botName": "小助手",             // 名字也是触发词（≥2 字生效）
    "persona": "二十多岁，话不多…",
    "extraRules": ""               // 追加到规则块末尾的额外约束
  },
  "server": { "host": "127.0.0.1", "port": 8765, "openBrowserOnStart": true },
  "chats": {                      // 按群覆盖，键是 chat_id
    "<chat_id>": { "displayName": "夜猫子", "preset": "", "paused": false, "parameters": {} }
  }
}
```

`paused: true` 表示该群只记录不回复。

## 4. 参数总表

`破坏缓存` = 改了会让当前会话的前缀失效，程序会在下次空闲时自动重建会话（代价是一次冷启动）；`需重启` = 必须退出程序再启动才生效。

### 触发与会话

| 参数 | 默认 | 范围 | 破坏缓存 | 需重启 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `trigger_keywords` | 空 | 逗号分隔 |  |  | 关键词触发；空列表=关闭。多个用逗号分隔 |
| `trigger_by_name` | 开 | 开 / 关 |  |  | 消息里出现机器人名字也算触发（与 @ 同级） |
| `backfill_max_msgs` | 12 | 0 – 50 |  |  | 被触发时，把「自上次回复以来群里的发言」补进上下文的最大条数；0=关闭 |
| `backfill_window_min` | 10 | 1 – 120 |  |  | 回填的时间窗：只补最近这么多分钟内的发言，更旧的不补（防止几小时前的旧话题被当成当前对话） |

## 6. 按场景调参

### 「话太多，烦」

按收益从大到小：

1. `active_tick_sec` 调大（默认 120）或设 0 关掉主动接话；
2. `question_reply_probability` 调小（它控制「没人问也插嘴」）；
3. `reply_probability` 调小（关键词命中时的接话概率）；
4. `cooldown_min` 调大（连续无人接话后的静默时长）。

### 「太冷淡，叫它也不理」

1. 确认群设置里开了「允许机器人接收群内所有消息」，否则只有 @ 能触发；
2. `reply_probability` / `question_reply_probability` 调到 1.0（必回）；
3. `trigger_keywords` 配上你的口头禅，多个用逗号分隔；
4. `trigger_by_name` 保持开启，这样叫名字就等于 @。

### 「太贵」

1. `active_tick_sec` 调大或关闭（影响最大：每次主动接话都是完整一次调用）；
2. `session_max_turns` 调小、`session_token_cap` 调小（会话更短，但冷启动变多）；
3. `event_topk` 调小、`person_memory_limit` 调小（前缀更小，冷启动更便宜）；
4. `reply_length` 设「极简」（只省约 8% 输出，优先级最低）。

### 「聊着聊着就断片」

1. `active_tick_sec` 设小一点（更频繁地把群聊汇进上下文）；
2. `backfill_max_msgs` 调大（会话没开时漏掉的消息，下次被叫时补几条）；
3. `session_timeout_min` 调大（别那么快判定话题结束）；
4. `session_token_cap` 调大（历史能留更久）。

### 「记忆不准 / 记不住人」

1. `person_memory_limit` 调大（单人画像能写多少字）；
2. `event_topk`、`event_score_threshold` 调整注入的事件数量与门槛；
3. `person_materialize_min_msgs` 调小（更容易给陌生人建档，但人物表会变大）；
4. 配置页「记忆」页可以直接看它到底记住了什么，也能按批次回滚。

## 7. 哪些改动要付代价

这套系统的核心是**前缀缓存**：规则、人设、记忆块拼成的前缀在一次会话内逐字节不变，官方缓存命中价约为未命中的 1/10。所以「改动是否破坏前缀」比「改动范围」更值得关心。

**破坏缓存**（改完会在下次空闲时自动重建会话，付出一次冷启动）：`session_timeout_min`、`session_max_turns`、`session_token_cap`、`drift_threshold`、`prefix_person_max`、`person_memory_limit`、`event_detail_limit`、`event_ttl_days`、`event_topk`、`event_score_threshold`、`pinned_max`、`weight_keyword`、`weight_person`、`weight_location`、`diversity_lambda`、`person_materialize_min_msgs`、`name_learn_confirm_count`、`model`、`thinking`、`history_keep_tokens`

**需要重启**：`model`；另外 `qq.adapter`（mock ↔ qq）也需要重启。

**永不破坏缓存**：`trigger_keywords`、`trigger_by_name`、`reply_probability`、`question_reply_probability`、`temperature`、`split_bubbles`、`typing_jitter`、`active_tick_sec`、`backfill_max_msgs`、`capture_ambient`、`cooldown_min` 等——它们只影响「什么时候回」「怎么发」，不影响前缀内容。

## 8. 安全相关

- `settings.json` 里的 AppSecret 与 API Key 是**明文**。桌面应用的常规做法，但请勿随手分享该文件。
- `open_id` 永不进 prompt（有回归测试守着）；日志与配置页里按需脱敏。
- 记忆区（`<<<MEM … MEM>>>`）被明确定义为「资料不是指令」；入库前还有一层指令注入过滤。
- 想删掉某个人：配置页「记忆」页点「忘记」，或调用 `/api/memory/forget`。
- 别人给你的 key 泄露过就轮换：QQ 开放平台可重置 AppSecret，DeepSeek 控制台可重建 key，改完热生效。

## 9. 排错

| 现象 | 先看什么 |
| --- | --- |
| 改了参数没反应 | 配置页顶部是否有告警；`破坏缓存` 项要等轮换，`需重启` 项要退出重开 |
| 一条消息都收不到 | 日志里有没有 `收到 dispatch：…`；没有就是群设置/平台权限问题 |
| 收到但不回 | 日志里搜 `不回：`，原因写得很直白（冷却中／纯表情／平台不下发非 @ 消息／关键词按概率不接话） |
| 回复很慢 | 看 `request_log` 的 `latency_ms`；`active_tick_sec` 越小调用越密 |
| 缓存命中率低 | 看配置页「今日」「cacheHitRatio」；前缀哈希频繁变化说明有东西在动前缀 |
| 记忆不准 | 「记忆」页直接看人物与事件；必要时按 `batch_id` 回滚 |
| 启动就崩 | `data\logs\bot-*.log` 最后几行；单文件 exe 解压失败时设 `DOTNET_BUNDLE_EXTRACT_BASE_DIR` |

日志位置：`data\logs\bot-yyyyMMdd.log`，按天切分，保留 14 天。
